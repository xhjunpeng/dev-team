# 隔离开发演练：订单导出

本项目只使用虚构订单和 Python 标准库，不连接任何业务系统。初始实现有意保留缺陷，用于取得真实失败信号；这不是线上发现的问题。

## 产品完成标准

输入为 JSON 二维数组：外层是分页，内层是订单。每条记录包含 id、customer、amount、currency、status、updated_at；时间为含时区的 ISO 8601，amount 原样保留为字符串。

1. 同一 id 只保留实际更新时间最新的记录；相同时间保留最后遇到的记录。
2. 先确定每个 id 的最终记录，再导出 status 为 paid 的订单。最新状态变为 cancelled 时不能导出早期 paid 版本。
3. 输出顺序按 id 第一次出现的顺序，更新版本不改变该顺序。
4. 不修改输入对象。CSV 列固定为 id、customer、amount、currency；正确处理中文、逗号、引号和换行，空结果仍保留表头。
5. 命令行 `python3 export_orders.py orders.json` 从文件读取，CSV 写到标准输出。

## 本次演练终点与范围

完成实际缺陷修复、全部目标及回归检查、一次全新上下文接续和独立只读验收，交付过程证据与问题清单。只可修复 fixture/export_orders.py；测试和本规格由主任务维护，执行员不得降低标准。既有技能源码、全局配置、Git 状态和外部服务均不属于实现范围。

阶段一修复目标用例，阶段二由没有历史对话的接手者读取短交接并完成剩余回归，阶段三独立验收。这个人为划定的阶段边界用于观察交接行为，不冒充真实自动压缩、应用重启或多日运行。
