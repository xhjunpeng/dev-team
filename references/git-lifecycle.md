# Git 候选与操作

## 开发目录

写入前按已加载的全局“项目文件与任务归属”规则核对候选及会话对应，复用其记录。未加载全局规则时，Codex 桌面端一个开发会话只在应用确认关联的工作树内编辑和执行生成产物的验证；同目标复用候选。

上一整体目标已完成并合并，且下一目标已获授权并明确超出原任务范围时，核对无待保留改动、其他写入者或旧版本运行依赖后，可在当前独立工作树同步主线并建立新任务分支，不因换批次自动另建目录。确需另一工作树时，先按授权完成承接会话的关联；工具不支持就说明具体操作并暂停受影响写入，不能手动跨目录绕过。共享本地目录仅在用户明确要求直接开发时使用；只读查看依赖不受此限。其他环境按实际并发和改动归属选择隔离方式。worktree 不隔离数据库、端口或缓存。

## Git 动作与清理

提交、推送、PR、合并、删除和外部操作分别核对已有授权及准确对象，不从本地完成推断发布权限。稳定环境中的连续编辑不反复检查全部 Git 状态；首次写入、交接、状态变化、交付和外部动作前核对相关事实。

合并按变更内容的实际风险和项目保护规则分级。普通合并先核对本次 diff、目标分支及保护规则，记录其不涉及权限、重要数据、生产或其他高风险后果的依据，再按已有授权和必要检查执行。高风险合并、强推和可能丢失成果的删除使用严格协议。已有严格任务和旧协议记录继续满足其约束。

常规本地清理可不派独立验收，但须已有准确删除授权、证明目标已合并到指定保留分支、工作树无已跟踪/未跟踪/忽略文件待保留，且没有任务、进程或终端使用它。删除 worktree 前通过应用查询真实会话关联；空闲、进程检查或文字记录不能代替该查询。仍需使用的会话先验证移交成功；工具不可用、移交失败或关联不明时保留目录，单独报告清理未完成。这里的会话移交只用于保护待删除工作目录，不影响在当前任务中手动调用 `dev-team`；普通收口也不授权归档会话。

v6 的 safe_cleanup 仅适用于本地 branch-delete/worktree-delete。校验器核对本地分支或已登记 worktree、Git 祖先关系和目录内容；unused_evidence 由主任务核对实际占用，不能由记录证明。远端分支删除、放弃未合并成果仍走严格动作，不用该字段降级。

收口前检查真实 diff、验证结果和成果去向；推送后核对远端。报告本地完成、提交、发布、合并、清理的真实状态，不把任务记录状态当成已经上线。
