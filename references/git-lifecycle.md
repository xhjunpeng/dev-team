# Git 候选生命周期

Git 动作由主任务管理，先读项目根、主分支、当前分支、工作区、worktree、候选归属和远端状态。适用项目的技术、安全与仓库约束按平台优先级处理；dev-team 负责当前协作与动作授权，不叠加第二套流程。

## 隔离

只读任务不建候选。同一未完成目标已有准确候选就复用，新会话或验收不另建分支。清晰可逆小修可在当前合适工作区直做；需要独立历史、PR 或跨会话交付时采用候选分支。并行目标、运行态绑定、其他人脏改动或高风险隔离需求时使用独立 worktree，准确名称和路径必须在已授权动作内。

已完成或无关脏改动先确认去向；归属不清不启动新写入。不能因分支名像旧任务认定归属，也不能因工作区干净认定已合并。worktree 只隔离文件，不自动隔离端口、数据库或缓存。

实时门禁核对真实 Git 根、分支、工作目录、基线祖先和 diff。主分支优先由 `refs/remotes/origin/HEAD` 解析，缺失时用 `dev-team.primaryBranch`；实际处于主分支时隔离必须为“主分支直接写”。状态不能把当前候选自报为主分支。稀疏检出、gitlink 和特殊索引状态按协议拒绝，以免漏掉范围变化。

## 动作与对象

提交、推送、PR、合并、同步分支、删除分支和删除 worktree 分别核对动作与准确对象。`planned_actions` 只能消费 `granted_actions` 中同名同对象的动作，PR 授权不覆盖合并或删除。已知高风险 Git 动作即使标为 reversible 也须有影响、回滚，并在实际执行前通过独立验收；终点名称不产生动作授权。

普通项目请求已授权的候选准备和必要验证连续执行，未覆盖的提交或外部动作待明确同意。对象表示法见 [executable-protocol.md](executable-protocol.md)。v2–v4 仍以旧授权卡及精确 `1` 约束，不能热切换。

## 内部收口审计

实际执行 Git 收口前核对准确候选、worktree、状态、暂存文件、diff 检查、作者、基线/祖先、远端与 PR/保护/检查状态；合并和清理的授权独立于本地通过和 PR 可评审。推送后重新取远端事实确认本地与远端一致；未运行的检查单独报告。

只清理已授权的准确候选，且必须证明成果已合并或有明确保留去向、独有提交均有去向、工作树干净且未跟踪内容已处理、没有进程/任务/终端继续使用目录。证据缺失保留候选，不扩大到其他分支、目录或数据。

## 完成与建议

固定验收完成且没有当前阻塞、未决范围或未批准质量例外时停止返工，分别报告本地候选、提交、推送、PR、合并、清理和实际启用状态。已验证未提交成果建议合适 Git 下一步；建议不是授权。

除明确复用同一未完成目标外，脏成果去向未决会阻止新目标。主任务给出收口、明确保留或独立工作区的适用选择，未决定时保留。收口状态与交接由同一 [任务记录](candidate-ledger.md) 提供。
