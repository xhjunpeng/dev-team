# 模型与角色

新开发任务使用 GPT-6 系列（包含 GPT-6.1 Sol）。主任务保留用户在平台选择的模型；指定模型不可用时说明阻塞。模型选择不改变读写权限、授权范围或验收要求，普通任务优先减少不必要委派。

## 默认分工

| 角色 | 模型与思考强度 | 负责的工作 |
| --- | --- | --- |
| 主任务 | 推荐 GPT-6.1 Sol；沿用用户选择的强度 | 理解目标、整体方案、跨模块判断、集成与交付；普通任务可直接完成 |
| 开发执行员 | GPT-6.1 Sol / high | 范围明确的非 UI 实现、修复与相称验证 |
| 界面制作员 | GPT-6.1 Sol / high | UI 设计、实现及实际页面的交互和响应式检查 |
| 独立验收员 | GPT-6.1 Sol / high | 全新只读上下文核查稳定候选及原始证据，必须不同于写入者 |
| 项目勘察员 | GPT-6 Luna / high | 目标和完成标准明确的定点只读事实查询；根因不明或跨模块判断交回主任务 |

最困难、需要持续跨步骤判断的整体任务，可由用户在平台选择 GPT-6 Astra；其余复杂编码、界面操作和长期执行优先考虑 6.1 Sol。三类执行角色保留 high，作为本团队的默认档位；是否适合降低强度，应以实际任务结果判断。

## 调用与兼容

实际派单前核对工具是否支持指定模型与档位，以真实调用及回执记录结果。主任务的模型切换须由平台完成，提示词不能改变正在运行的模型。用户另行指定模型或强度时，同步调整角色配置和相关校验；固定角色不可用时，不用临时通用 Agent 绕过分工。修改配置不会改变已经启动的执行员。

v6 不检查固定模型组合，实际派单以角色配置为准。v5 的旧模型字段保留历史兼容；准备执行新动作时，当前派单须匹配角色配置，并按 [旧协议](legacy-protocol.md) 记录模型覆盖及原有授权依据。v2–v4 没有结构化模型字段，实际调用须核对工具回执。角色提示词不是沙箱；按平台实际权限与行为约束执行。

## 选择依据

2026-09-30 核对 [GPT-6.1 Sol 官方说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol) 与 [Codex 模型选择](https://developers.openai.com/codex/models#choosing-astra-sol-and-luna)：6.1 Sol 用于复杂编码、计算机操作和专业工作，官方定位为接近 Astra 的能力、成本更低；Luna 用于明确、可重复的任务，Astra 保留给最困难的整体工作。这是本团队的分工选择，尚未通过本项目对比评测证明 6.1 Sol 与 Astra 的结果相同。
