# 模型与角色

新开发任务的四个预设角色使用以下固定模型与思考强度。主任务沿用用户选择的 GPT-6 模型；若当前任务仍运行旧模型，须先通过平台切换，不能靠提示词声称已经切换。指定模型不可用时说明阻塞，不回退旧模型或自行替换角色模型。模型选择不改变读写权限、授权范围或验收要求，普通任务优先减少不必要委派。

- 开发执行员、界面制作员、独立验收员：GPT-6 Sol/high。验收员仍须只读、全新上下文且不同于写入者。
- 项目勘察员：GPT-6 Luna/high，只接目标和完成标准明确的定点只读事实问题；根因不明或跨模块判断交给主任务处理。

实际派单前核对工具是否支持指定模型与档位。普通子任务记录实际调用及结果即可；用户另行指定其他模型或强度时，再按该要求调整角色配置和相关校验，不以临时通用 Agent 绕过固定分工。

v6 不检查固定模型组合，实际派单以角色配置为准。v5 的旧模型字段保留历史兼容；准备执行新动作时，当前派单须匹配角色配置，并按 [旧协议](legacy-protocol.md) 记录模型覆盖及原有授权依据。v2–v4 没有结构化模型字段，实际调用须核对工具回执。角色提示词不是沙箱；按平台实际权限与行为约束执行。
