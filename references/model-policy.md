# 模型与角色

新开发任务使用 GPT-6 系列（包含 GPT-6.1 Sol）。主任务保留用户在平台选择的模型；指定模型不可用时说明阻塞。模型选择不改变读写权限、授权范围或验收要求，普通任务优先减少不必要委派。

## 默认分工

| 角色 | 模型与思考强度 | 负责的工作 |
| --- | --- | --- |
| 主任务 | 推荐 GPT-6.1 Sol / xhigh；保留用户在平台的选择 | 理解目标、整体方案、跨模块判断、集成与交付；普通任务可直接完成 |
| 开发执行员 | GPT-6.1 Sol / high | 范围明确的非 UI 实现、修复与相称验证 |
| 界面制作员 | GPT-6.1 Sol / high | UI 设计、实现及实际页面的交互和响应式检查 |
| 独立验收员 | GPT-6.1 Sol / xhigh | 全新只读上下文核查稳定候选及原始证据，必须不同于写入者 |
| 项目勘察员 | GPT-6 Luna / high | 目标和完成标准明确的定点只读事实查询；根因不明或跨模块判断交回主任务 |

`xhigh` 对应平台显示的 Extra High。

## 按任务调整

开发涉及跨模块状态、权限、事务或并发判断，或 UI 涉及复杂多状态、跨端交互判断时，可将该阶段执行角色升为 xhigh；范围清楚的实现保持 high。项目勘察员遇到根因不明或跨模块判断，交回主任务，不把定点事实查询扩大成整体诊断。

主任务处理能明确拆分、并行后仍可集成的长任务时，可由用户在平台选择 Ultra；Max 留给少数需要集中深入判断的难题。最困难的整体任务仍可考虑 GPT-6 Astra。依据任务难点和新证据调整，失败次数本身不触发升档；没有新证据时先改善诊断，不能靠加大思考强度重复旧假设。

## 调用与兼容

实际派单前核对工具是否支持指定模型与档位，以真实调用及回执记录结果。主任务的模型切换须由平台完成，提示词不能改变正在运行的模型；主任务选择 Ultra 也不会覆盖子角色的固定设置。

需要升档或用户另行指定模型、强度时，优先使用平台已支持的任务级设置。固定角色无法在本任务单独升档时，将相关阶段交给具备所需强度的主任务处理或说明限制；升档建议本身不授权修改所有聊天共用的配置。获准调整角色配置时，同步相关校验并重新加载，再按回执核对新派单。修改配置不会改变已经启动的执行员；职责交接仍由主任务协调，不用临时通用 Agent 绕过分工。

v6 不检查固定模型组合，实际派单以角色配置为准，机器校验从角色模板读取配置，避免重复写死模型和档位。v5 的旧模型字段保留历史兼容；准备执行新动作时，当前派单须匹配角色配置，并按 [旧协议](legacy-protocol.md) 记录模型覆盖及原有授权依据。v2–v4 没有结构化模型字段，实际调用须核对工具回执。角色提示词不是沙箱；按平台实际权限与行为约束执行。

## 选择依据

2026-10-22 核对 [官方模型与档位说明](https://learn.chatgpt.com/docs/models)、[子代理配置说明](https://learn.chatgpt.com/docs/agent-configuration/subagents) 及 [GPT-6.1 Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)，用于确认模型定位、档位和角色配置行为。上述组合是偏重减少返工的团队默认选择，尚无本团队不同档位的对照结果，不代表 xhigh 必然优于 high，也未证明 6.1 Sol 与 Astra 的结果相同。
