# 难度与操作影响

难度决定需要多少推理与协作；操作影响决定授权、隔离、回滚和验收。文件数不作为风险等级。复杂的只读分析可以由主任务完成，简单的一次数据删除仍是高风险。

| 路径 | 情况 | 最小执行方式 | 完成条件 |
| --- | --- | --- | --- |
| 快速 | 明确只读任务或局部可逆小修 | 主任务直做；不为机械改动额外派单 | 直接结果和相称检查 |
| 标准 | 普通功能、明确 Bug、多文件实现 | 一个开发执行员或界面制作员；仅缺明确事实时勘察 | 固定检查、自检、主任务核对真实 diff |
| 严格 | 安全权限、数据、生产、付费、外部发布、破坏性 Git 或难回滚改动 | 唯一执行员与全新只读独立验收；准确对象、影响、回滚与授权 | 固定检查和独立验收通过，外部边界明确 |

任务记录 `task_assessment.difficulty` 为 `small / normal / complex`，`operation_risk` 为 `read-only / reversible / high-risk`。已知高风险动作由校验器识别，不能以自报 reversible 降级。复杂度本身不授权任何写入；高风险独立验收不能被自检替代。

普通任务触及共享状态、接口、结构性改动或已有失败记录时，主任务判断是否需要独立验收并记录理由。只读工作一般不派单，用户明确要求或确有独立事实问题时可派只读勘察。

新证据支持局部且可逆时可降级；未知副作用、候选冲突、超范围或关键验证缺口则升级或停止。升降级保持同一记录与失败历史。方法选择见 [specialist-routing.md](specialist-routing.md)，模型选择见 [model-policy.md](model-policy.md)。
