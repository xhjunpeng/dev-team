# 轻重路由

先选择最小够用路径。文件数量不是风险级别；依据是清晰度、可逆性、影响范围和验证能力。

## 快速路径

适用于只读回答、明确查找、机械检查，或局部且可逆的机械小修。只读工作由主任务直接完成。小修一旦需要修改项目文件，默认只派一个开发执行员作为唯一写入者，不额外派勘察员或独立验收员；只有最新动手清单明确授权“主任务直接写”时，主任务可例外写入。UI 专项规则优先于本路径。

完成条件：目标结果已产生；写入任务通过工程质量门禁，并执行与改动相称的直接检查。

## 标准路径

适用于普通功能、页面、明确 Bug 或有边界的多文件实现。按需使用项目勘察员，再选择一个开发执行员或界面制作员作为唯一写入者。

完成条件：范围内改动完成，针对性验证通过，主任务检查实际 diff、权威实现、替换/删除项、技术债变化和结果。触及已有热点、重复或覆盖区，共享接口、状态或数据模型，结构性重构或失败修复记录时，独立验收具有真实判断价值。

## 严格路径

权限、认证、迁移、安全、用户数据、生产、付费、外部发布、破坏性 Git、难回滚架构、复杂并行或重大验收进入严格路径。

要求：准确候选与回滚边界、较高推理档位、稳定验证信号、全新只读独立验收分别确认功能结果与实现质量，以及对未运行检查和外部状态的单独报告。

## 升降级

- 勘察后发现任务确定、局部且可逆，可以降级，不完成剩余仪式。
- 找不到权威实现、干净实现需要扩大授权范围、出现后置覆盖或平行实现、存在未知副作用、候选冲突或验证缺口时升级或停止。
- 只读工作不强制派单；项目文件写入不因协调成本留在主任务，除非最新动手清单明确授权“主任务直接写”。
- 不为机械任务固定创建评审，不为高风险任务用“测试绿了”替代独立判断。

## 专项 Skill 不改变风险路径

先选择快速、标准或严格路径，再决定当前阶段是否需要一个专项 Skill。专项 Skill 不能把严格任务降级，也不能把机械任务自动升级成长流程。

- 任务清楚且项目现有方法足够：记录“不使用额外 Skill”并继续。
- 需要专业方法：按 [specialist-routing.md](specialist-routing.md) 选择当前阶段唯一的主要专项 Skill。
- Skill 仅用户可调用：给出可复制命令、影响和返回条件，不自动调用或模拟。
- Skill 不可用或与项目规则冲突：项目规则优先，报告替代方法和未验证边界。
