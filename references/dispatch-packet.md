# 派单包

派单前必须能写清收益、边界和停止条件。缺少关键字段时不要启动子 Agent。

```text
协作模式：已启用
任务包版本：1
任务名称：
使用角色：
派单收益：
目标结果：
项目与准确候选路径：
已知证据：
允许读取：
操作权限：只读 / 工作区写入
实际生效权限：
唯一写入范围：
质量规范：
目标行为与权威实现：
复用项：
替换/删除项：
新增概念、状态、抽象或依赖及理由：
既有债务边界：
质量验收：
明确排除：
用户授权状态：
写入授权：未获得 / 已获得
主任务直接写：不允许 / 最新动手清单已明确授权
已确认 Design Read（UI 任务）：不适用 / 待确认 / 已确认
必须执行的检查：
遇到什么立即停止：
返回格式：
故障编号（如适用）：
当前修复尝试次数（如适用）：
故障信号与假设（如适用）：
```

写入或验收任务必须填写全部质量字段；不适用时写明原因。找不到权威实现，或干净实现需要扩大唯一写入范围时，任务包保持不完整并退回主任务决定。

## 角色返回

- **项目勘察员**：事实、证据位置、推测、冲突、未知项和最小下一检查。
- **开发执行员**：改动、文件、权威实现、复用与替换/删除、新增概念或依赖、质量检查、技术债变化、功能验证、未运行检查和剩余风险；不倾倒完整日志。
- **界面制作员**：Design Read、页面和状态范围、权威结构与样式、复用与替换/删除、实现文件、质量检查、响应式与交互自检、技术债变化和遗留问题。
- **独立验收员**：功能结果、实现质量、新增技术债、P0-P3、证据、影响、最小修复方向、所需验证、最终结论和未验证边界。

原始日志留在子线程；主任务接收可复查的命令、结果和关键错误。任务协调员等待并整合一次，不重复调查或轮询已知事实。

项目文件写入默认必须派给一个合适的子 Agent。机械小修只派一个开发执行员；不额外派项目勘察员或独立验收员。主任务直接写仅在最新动手清单明确写出“主任务直接写”时允许，并把该授权原文和唯一写入范围写入任务包。

Agent TOML 中的 `sandbox_mode` 是默认配置，不是实际隔离证据。派单前核对父任务当前权限和子线程实际生效权限；只读角色即使运行环境更宽，也必须保持只读并在权限边界不清时停止。
