# 协作与交接

只在能减少等待或提供独立核验时派单。派单提供：目标与约束、准确目录、负责文件或模块、必要证据入口、完成标准。引用已有位置，不复制整套规则。普通协作无需机器状态；严格任务附 v6 状态绝对路径与权威 Skill 根；旧任务附原版本状态。

主任务核对聊天授权，子任务按收到的范围执行，不因看不到主对话重复请求用户同意。明确告诉执行员其他人也在工作，保留他们的改动。每个文件或紧密关联范围只交给一个写入者；目录互不重叠也不保证接口独立，共享接口、锁文件和集成由一个负责人处理。需要改动他人范围时先交回主任务协调。

主任务可同时承担明确不重叠的写入范围。写入者变更前结束旧职责，交付前汇总 diff 并运行必要集成检查。普通子任务不继续派生；确需更深分工由主任务统一安排，避免隐藏写入冲突。

严格任务在首次接手、环境变化和交付时运行实时门禁；连续编辑无需每次重复。验收员使用全新只读上下文，拿到目标、约束、稳定候选、既有验收证据及后续变化，不把开发者总结当作证明。按 [工程质量](engineering-quality.md) 核对原始证据并补验受影响部分；最终候选按 [严格协议](executable-protocol.md) 重新确认，不能只刷新指纹代替验收。

局部验收期间稳定其检查范围及依赖，无关模块经确认独立后继续推进；共享接口或依赖变化交回主任务协调。严格状态已有阻塞时仍遵守 blocked 门禁；验收中的正常等待不自动成为整个任务的阻塞。最终交付汇总当前候选并完成必要集成检查。

返回实际改动、验证结果、未验证边界和下一动作或阻塞即可。主任务按 [任务记录](candidate-ledger.md) 更新进度，阶段完成后推进到原已授权终点。
