# 实现与验证

围绕已确认的目标修改权威实现，复用现有能力，检查被替换路径是否仍在生效。主任务自行选择实现步骤和验证方法；已有项目约束直接复用。

检查与实际影响相称：Bug 验证原始症状，功能验证可观察行为，UI 验证真实页面和交互。相邻回归或外部环境确实相关时再加入检查，不固定要求三类记录，不为小改动编写镜像测试。

完成前查看实际 diff 和必要运行证据。无关旧问题不阻塞；当前改动引入的问题与实现目标必需的问题要解决。会改变业务、范围或交付结果的取舍交给用户；常规实现选择由主任务判断。

## 重验与证据复用

检查通过后，沿用适用条件未变的证据。重跑前在已有进度或检查结果旁简短说明：什么变化或失败使哪项结论需要复核、哪个检查能回答；无需新建记录或逐次审批。新增检查须对应目标必需的缺口、本次引入的问题或适用项目规定，完成标准不随检查次数增加。

证据关联实际验证的代码版本或内容、行为与必要环境/数据条件。变化时沿调用与依赖关系判断影响，覆盖公共组件、权限、配置、数据库结构和验证工具本身；文件不重叠不能证明独立。只补受影响检查；无法划清影响时补能消除该不确定性的回归或集成检查。交接、上下文恢复、Git 提交位置或验收指纹变化本身不要求全量重跑。

版本确认与行为重验分别处理：核对变化、保留仍适用的原始证据，补验受影响部分后再确认当前候选。项目明确要求最终源码重新构建或验收时仍执行该要求，不能用技能的复用规则绕过。最终完成适用的集成检查。

为验证目标临时编写的脚本或工具，以能可靠识别当前问题、提供所需证据为结束条件。验证会影响结论的工具行为，修正误判风险；已有入口足够时直接使用。额外通用化、工具治理或完整开发/预审/后验流程只有当前目标确需时才加入。

严格任务将必要检查写入 v6 的 checks。协议只检查记录和 Git 一致性，不能证明命令运行、用户同意或业务正确；真实证据仍需核对。
