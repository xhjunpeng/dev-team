# 项目发现

只查明当前结果所需的事实，不把只读问题扩大为全仓扫描、启动服务或创建候选。

写入前确认项目根、真实源码入口、相关配置与测试、当前分支、Git 主分支、工作区内容、候选归属及唯一写入者。适用的 `AGENTS.md`、`CLAUDE.md` 和它们指向的项目文档必须按作用范围读取，采纳技术栈、接口、数据、安全、格式、构建和验收约束；不因使用 dev-team 就排除项目规则。冲突按平台指令优先级处理，不能自创“项目总是优先”或“Skill 总是优先”。同一事项已由适用流程覆盖时引用它，不重复加一套审批或协调流程。

确认目标权威实现、可复用组件与接口、要替换的旧路径、现有质量检查和固定验收。已有问题分为当前阻塞、无关记录和新增范围，见 [engineering-quality.md](engineering-quality.md)。

依赖服务时核对 PID、命令、cwd、端口、路由和依赖。浏览器截图须来自准确候选；端口可用或日志显示启动不能证明目标服务正确。凭证只确认是否可用，不读取或展示无关秘密。

连续执行可以包含按工作树既有锁文件恢复依赖及生成本地验证产物；修改依赖版本、锁文件或外部状态须重新核对是否已获授权。首次找到同一目标的权威入口、共享接口或固定测试接缝，先在唯一状态中记录可审计来源与动作范围，再继续，不能用新增路径绕过排除项。

恢复会话、上下文压缩或切换目录后重查可能变化的 Git、服务、权限和范围；旧摘要只用于定位证据。事实回报包含来源、结论、未知项及最小下一检查，写入前候选判断见 [git-lifecycle.md](git-lifecycle.md)。
