# 项目发现

只收集当前任务需要的事实。环境和项目文件是事实来源，不在 Skill 中维护项目副本。

## 最小发现

1. 确认当前目录、项目根目录和任务目标。
2. 读取当前范围适用的规则和它们直接指向的资料。
3. 识别技术栈、现有脚本、测试入口和真实源文件。
4. 区分已验证事实、合理推测和待验证事项。

只读问题到此即可。不要因为调用了协作 Skill 就启动服务、创建候选或扫描全部仓库。

## 写入前补充

写入任务还要确认：

- Git 主分支、当前分支、未提交和未跟踪内容。
- 已有候选、worktree、任务归属和合并状态。
- 本轮唯一写入范围，以及是否与用户或其他 Agent 重叠。
- 项目规定的构建、测试、格式和验收命令。
- 当前行为的权威实现、可复用项、需要替换或删除的旧路径，以及触及范围内已有的重复、覆盖区或复杂度热点。
- 项目已有的代码质量、重复率、复杂度或体积检查；没有时不发明机械行数阈值。
- 需要的凭证、外部系统、费用和数据边界；不要读取或展示秘密。

运行态只有在任务依赖真实页面、服务、端口、数据库或进程时才检查。此时核对监听进程、PID、命令、cwd、路由和依赖，不把“端口可用”或“启动日志”当作目标服务证据。
