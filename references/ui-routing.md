# UI 路由

已有精确答案、无需设计判断的局部机械 UI 小修可由主任务直做；普通页面或需要视觉、布局、交互、响应式、动效、组件状态判断时，使用唯一界面制作员。默认 `finesse-ui` 是唯一视觉权威；用户指定照图时可用 `product-design:image-to-code`。辅助组件工具不另定视觉方向。

先做相称的 Design Read：目标页面与状态、可见方向、保留内容、改动范围、权威结构/样式、复用与替换、图片计划及验证方式。没有会明显改变结果的关键选择且写入已获授权，可直接实现；存在关键未决选择时只完成读和准备，并交回主任务。Design Read 不产生额外写入或外部权限。

已有产品使用 `verification_mode=existing-ui`：捕获真实页面/状态，保留既有 AppShell、导航、组件、token 和业务规则，除非授权包含它们。先核对浏览器实际候选、进程和路由。全新 UI 使用 `new-ui`，`before_status=not-applicable` 并解释不存在旧页面，不制造历史截图或伪造基线。两者均验证真实入口、关键交互、响应式及适用的可访问性/控制台问题。

图片生成或获取按当前用户意图与具体资源权限执行，已有明确授权不再重复询问；外部费用、敏感素材或未覆盖的副作用交回决定。写入者自检结构、状态和样式各自唯一的权威来源；独立验收需要时从全新只读上下文检查稳定候选，不能由制作员验收自己。质量和例外见 [engineering-quality.md](engineering-quality.md)。
